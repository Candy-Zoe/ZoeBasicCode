C# 完全教程

从零基础到深入原理，全面掌握 C# 与 .NET 开发。涵盖 CLR 内存模型、GC 分代回收、委托内部机制、async 状态机等核心原理。

1. C# 简介

C#（读作 "C Sharp"）是微软于 2000 年发布的一门现代、面向对象的编程语言，由 Anders Hejlsberg 主持设计。C# 运行在 .NET 运行时之上，兼具类型安全、高性能和丰富的生态，广泛应用于企业应用、Web 开发（ASP.NET）、游戏开发（Unity）、桌面应用（WPF/MAUI）和云原生服务。

语言定位

C# 从 C/C++ 和 Java 中汲取了大量设计理念，同时不断演进——从 C# 1.0 的基本面向对象，到 C# 3.0 引入 LINQ 和 Lambda，C# 5.0 引入 async/await，再到 C# 12 的 primary constructors 和 collection expressions。C# 的设计哲学是："在安全性和生产力之间寻找最优平衡"。它通过强类型系统保证安全，通过语法糖和编译器智能提升开发效率。

C# 的核心特性

  • 类型安全：编译期强制类型检查，消除大量运行时错误
  • 自动内存管理：垃圾回收器（GC）自动管理堆内存，开发者无需手动释放
  • 委托与事件：一等公民级别的类型安全回调机制
  • LINQ：统一的数据查询语法，作用于内存集合、数据库、XML 等
  • async/await：原生异步编程模型，基于状态机编译转换
  • 泛型：编译期类型参数化，零装箱的类型安全容器
  • 模式匹配：强大的类型检查与解构语法
  • 跨平台：.NET 6+ 全面支持 Windows/Linux/macOS

var vs 显式类型的选择

方法重载

同一个类中可以有多个同名方法，只要参数列表不同（参数个数、类型或顺序）即可：

csharp 
public class Logger
{
    public void Log(string message)
    {
        Console.WriteLine(message);

11. 参数传递

C# 方法的参数有多种传递方式，决定了方法内部能否修改外部变量的值。

csharp 
public class ParamsDemo
{
    // 值传递（默认）：方法收到的是副本
    public void Increment(int x)
    {
        x++;  // 只修改了副本
    }

    // ref：传引用，方法可以修改原变量
    public void IncrementRef(ref int x)
    {
        x++;  // 修改的是调用者的变量
    }

    // out：输出参数，方法必须在返回前赋值
    public void Divide(int a, int b, out int quotient, out int remainder)
    {
        quotient = a / b;
        remainder = a % b;
    }

    // in：只读引用，避免大结构体的复制开销
    public double GetArea(in Rectangle rect)
    {
        return rect.Width * rect.Height;
    }

    // params：可变参数，接收任意数量的同类型参数

委托的内部机制

委托（Delegate）本质上是一个类型安全的函数指针，它继承自 System.MulticastDelegate。每个委托实例内部维护三个关键字段：_target（目标对象，静态方法时为 null）、_methodPtr（方法的 IL 地址）和 _invocationList（多播委托的调用链数组）。当调用委托时，CLR 通过 _methodPtr 跳转到目标方法，如果 _invocationList 不为空，则依次调用数组中的每个委托。多播委托的 Combine 操作会创建一个新委托，其 _invocationList 是两个委托的组合数组。

csharp

{

    public void Subscribe(NotifyHandler handler)
    {
        _onNotify += handler;  // 多播委托组合

    {
        _onNotify -= handler;
    }

    public void Publish(string message)
    {

LINQ 延迟执行

延迟执行原理

大多数 LINQ 操作是延迟执行的——查询表达式定义了查询逻辑，但不会立即执行。只有在枚举结果（如 foreach、ToList()、Count()）时才真正执行。这意味着你可以在运行时动态构建查询链。但 ToList()、ToArray()、Count() 等会立即执行并缓存结果。在循环中反复枚举同一查询可能导致重复执行，必要时用 ToList() 固化结果。

async 状态机的内部机制

编译器将 async 方法转换为一个状态机（IAsyncStateMachine 实现）。状态机包含：一个 state 字段（-1=初始，0=等待中，1=已完成）、一个 builder（ AsyncTaskMethodBuilder，管理 Task 的创建和完成）、以及捕获的局部变量。每次遇到 await，状态机检查 Task 是否已完成：如果已完成，直接继续执行；如果未完成，状态机将当前状态设为"等待中"，注册一个延续回调（Continuation），然后将控制权返回给调用者。当 Task 完成时，回调触发状态机恢复执行，从 await 的下一行继续。整个过程不阻塞线程——线程被释放回线程池去处理其他工作。

csharp 
// 编译器生成的状态机伪代码
struct FetcherStateMachine : IAsyncStateMachine
{
    public int _state;           // 状态标记
    public AsyncTaskMethodBuilder<string> _builder;
    private string _url;        // 捕获的变量
    private HttpClient _client;

    public void MoveNext()
    {
        switch (_state)
        {
            case -1:  // 初始状态
                _client = new HttpClient();
                var task = _client.GetStringAsync(_url);
                if (!task.IsCompleted)
                {
                    _state = 0;
                    _builder.AwaitUnsafeOnCompleted(ref task, this);
                    return;  // 挂起，返回线程池
                }
                goto case 0;
            case 0:   // 恢复执行
                string data = _client.GetStringAsync(_url).Result;
                _builder.SetResult(data);
                break;
        }
    }
}

25. 内存管理与 GC

CLR 内存模型

.NET 程序运行在 CLR（公共语言运行时）之上，内存分为两大区域：栈（Stack）和堆（Heap）。栈由系统自动管理，存储值类型变量和方法调用帧，遵循 LIFO 顺序，分配和释放极快（只需移动栈指针）。堆由 GC 管理，存储引用类型的对象实例。每个引用类型变量存储的是指向堆上对象的指针（4 或 8 字节）。当方法返回时，栈帧被回收，栈上的值类型变量随之消失，但堆上的对象仍然存在，等待 GC 回收。

托管堆的结构

托管堆在逻辑上是一个连续的内存空间。GC 维护一个分配指针（NextObjPtr），新对象总是分配在指针当前位置。当指针到达堆边界时触发 GC。对象在堆上的排列顺序和分配顺序一致，这意味着连续分配的对象在内存中也是相邻的，具有良好的缓存局部性。GC 还维护了代（Generation）体系来优化回收效率。

GC 分代回收机制

.NET GC 将对象分为三代：

代初始大小阈值特点回收频率
Gen 0~256 KB新分配的对象，大多数短命对象在这里被回收最高
Gen 1~2 MB存活过一次 GC 的对象，作为缓冲区中等
Gen 2~10 MB存活过两次 GC 的对象，长期存活对象最低
LOH≥ 85,000 字节大对象堆，大对象直接分配在此仅在 Gen 2 回收时
分代回收的原理

基于"弱分代假说"（Weak Generational Hypothesis）：大多数对象的生命周期很短（如临时变量、方法内的局部对象），少数对象会存活很久（如缓存、单例）。GC 利用这个假说：Gen 0 回收最频繁，只扫描 Gen 0 中的对象，标记存活对象并压缩，未存活的对象直接被回收。Gen 0 中存活的对象被提升（promote）到 Gen 1。Gen 1 回收作为缓冲，当 Gen 0 空间不足时触发，同时回收 Gen 0 和 Gen 1。Gen 2 回收扫描整个堆，是最耗时的操作。LOH（大对象堆）仅在 Gen 2 回收时才被处理，且默认不压缩（避免移动大对象的开销）。

GC 的标记-压缩算法

.NET GC 使用标记-清除-压缩三步算法：1. 标记（Mark）——从 GC Roots（栈变量、静态字段、CPU 寄存器等）出发，遍历所有可达对象并标记为存活。2. 清除（Sweep）——扫描堆，回收未标记的对象。3. 压缩（Compact）——将存活对象向堆的一端移动，消除内存碎片（LOH 不压缩）。压缩后更新所有引用该对象的指针。这个过程会导致短暂的"Stop-the-World"暂停，但 .NET 的增量回收和后台 GC 机制大大缩短了暂停时间。

Finalizer vs IDisposable 的区别

IDisposable 是确定性释放——开发者显式调用 Dispose() 或使用 using，释放时机确定。Finalizer（析构函数）是非确定性释放——由 GC 在回收对象前自动调用，时机不确定。Finalizer 作为安全网，防止忘记 Dispose 导致的资源泄漏，但有性能开销（对象进终结队列，需要两轮 GC 才能回收）。最佳实践：实现 IDisposable + using，Finalizer 仅作为最后保障。
