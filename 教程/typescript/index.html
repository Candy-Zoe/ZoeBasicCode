TypeScript 完整教程

从零开始掌握 TypeScript —— JavaScript 的超集，静态类型系统的实践指南，涵盖类型推断、泛型、类型体操、模块系统等核心知识。

1. 简介与安装

TypeScript 是由微软开发的开源编程语言，它是 JavaScript 的超集，在 JavaScript 的基础上添加了静态类型系统和其他高级特性。TypeScript 代码最终会被编译为纯 JavaScript 代码运行。

核心理念

JavaScript 有的，TypeScript 都有。TypeScript 在编译后会完全还原为 JavaScript，因此任何合法的 JavaScript 代码都是合法的 TypeScript 代码。TypeScript 的核心价值在于编译时的类型检查，帮助开发者在运行之前发现潜在错误。

安装 TypeScript

可以通过 npm 全局安装 TypeScript 编译器：

Bash
# 全局安装 TypeScript
npm install -g typescript

# 验证安装
tsc --version

# 在项目中初始化 tsconfig.json
tsc --init

# 编译 TypeScript 文件
tsc hello.ts

# 使用 ts-node 直接运行 .ts 文件（开发常用）
npm install -g ts-node
ts-node hello.ts

第一个 TypeScript 程序

TypeScript
// hello.ts
function greet(name: string): string {
    return `你好，${name}！欢迎学习 TypeScript！`;
}

const message: string = greet("TypeScript");
console.log(message);

// 类型错误示例 - 编译时会被捕获

2. 基础类型

TypeScript 提供了丰富的基础类型，每种类型都有明确的语义和使用场景。掌握基础类型是理解整个类型系统的基石。

原始类型

TypeScript
// 字符串类型
let name: string = "张三";
let greeting: string = `你好，${name}`;

// 数字类型（不区分整数和浮点数）
let age: number = 25;
let price: number = 99.9;
let hex: number = 0xff;
let binary: number = 0b1010;

// 布尔类型
let isActive: boolean = true;

// null 和 undefined
let nothing: null = null;
let notDefined: undefined = undefined;

// Symbol
let sym: symbol = Symbol("key");

// BigInt
let bigNum: bigint = 100n;

数组与元组

TypeScript
// 数组 - 两种声明方式
let numbers: number[] = [1, 2, 3];
let names: Array<string> = ["张三", "李四"];

// 只读数组
let readonlyArr: ReadonlyArray<number> = [1, 2, 3];
// readonlyArr.push(4); // ❌ 错误：ReadonlyArray 上不存在 push 方法

// 元组 - 固定长度和类型的数组
let person: [string, number] = ["张三", 25];
let coordinate: [number, number, number] = [10, 20, 30];

// 元组解构
const [personName, personAge] = person;

// 具名元组标签（TypeScript 4.0+）
type User = [name: string, age: number, email: string];
let user: User = ["李四", 30, "lisi@example.com"];

特殊类型

TypeScript
// any - 放弃类型检查（尽量少用）
let anything: any = "字符串";
anything = 42;      // 允许
anything = true;   // 允许
anything.foo();     // 允许（但运行时会报错）

// unknown - 安全的 any，必须先检查类型才能使用
let data: unknown = "这是一些数据";
// console.log(data.length); // ❌ 错误：unknown 上不存在 length 属性

// 必须进行类型检查
if (typeof data === "string") {
    console.log(data.length); // ✅ 正确：12
}

// never - 不可能出现的类型
function throwError(msg: string): never {
    throw new Error(msg);
}

// void - 没有返回值
function logMessage(msg: string): void {
    console.log(msg);
}

// 对象类型
let obj: object = { name: "张三" };

// 更精确的对象类型
let personObj: { name: string; age: number } = {
    name: "李四",
    age: 30
};
注意：应尽量避免使用 any 类型，它会绕过类型检查，失去 TypeScript 的核心优势。优先使用 unknown 代替 any，因为 unknown 强制进行类型检查后才能使用。

类型断言

TypeScript
// 类型断言 - 告诉编译器"我知道这个值的类型"
let someValue: unknown = "这是一个字符串";

// 尖括号语法
let strLength: number = (<string>someValue).length;

// as 语法（推荐，在 JSX 中也能用）
let strLength2: number = (someValue as string).length;

// 非空断言运算符（!）
function getLength(value: string | null): number {
    // 非空断言：告诉编译器 value 一定不是 null
    return value!.length;
}
慎用非空断言：非空断言 ! 会绕过空值检查，如果值实际上为 null 或 undefined，运行时会抛出错误。建议优先使用可选链 ?. 或空值合并 ??。

3. 类型推断

TypeScript 的类型推断（Type Inference）是其类型系统最强大的特性之一。编译器能够根据上下文自动推断变量的类型，减少显式类型注解的需要。

结构化类型系统

TypeScript 采用结构化类型系统（Structural Typing），也称为"鸭子类型"。类型的兼容性取决于结构而非名称。如果两个类型具有相同的结构（属性和方法），它们就是兼容的。这与 Java、C# 等语言的名义类型系统（Nominal Typing）有本质区别。

基础类型推断

TypeScript
// 基础类型推断 - 根据初始值推断
let x = 10;           // 推断为 number
let y = "hello";      // 推断为 string
let z = true;        // 推断为 boolean
let arr = [1, 2, 3];   // 推断为 number[]

// 函数返回值推断
function add(a: number, b: number) {
    return a + b; // 返回值被推断为 number
}

// 上下文类型推断
const names = ["张三", "李四", "王五"];
const upperNames = names.map(name => name.toUpperCase());
// name 的类型被推断为 string

最佳通用类型推断

TypeScript
// 当数组中有多种类型时，推断出"最佳通用类型"
let mixed = [1, "hello", true];
// 推断为 (string | number | boolean)[]

// 对象类型推断
const user = {
    name: "张三",
    age: 25,
    hobbies: ["编程", "阅读"]
};
// 推断为 { name: string; age: number; hobbies: string[] }

// 返回值类型推断
function createUser(name: string, age: number) {
    return { name, age, createdAt: new Date() };
}
// 返回值推断为 { name: string; age: number; createdAt: Date }

// 使用 ReturnType 获取推断的返回类型
type User = ReturnType<typeof createUser>;

类型推断的局限

TypeScript
// 空数组无法推断类型
let emptyArr = [];   // 推断为 any[]
// 需要显式指定类型
let typedArr: number[] = [];

// 函数参数需要类型注解
function divide(a, b) {  // ❌ 参数隐式推断为 any
    return a / b;
}

// 正确做法
function divideCorrect(a: number, b: number): number {
    return a / b;
}

// 宽字面量推断 - const 断言
let x = "hello";     // 类型为 string
const y = "hello";   // 类型为 "hello"（字面量类型）
const z = { a: 1 };  // 类型为 { a: number }

// as const - 将所有属性变为只读字面量类型
const config = {
    host: "localhost",
    port: 3000
} as const;
// 类型为 { readonly host: "localhost"; readonly port: 3000 }
类型推断最佳实践：在变量声明时有初始值的情况下，不需要显式类型注解。但在函数参数、空数组、对象属性等场景下，应显式指定类型以获得更好的类型安全性和代码可读性。

4. 接口

接口（Interface）是 TypeScript 中定义对象结构的核心方式。它描述了对象应该具有的形状（shape），包括属性、方法及其类型。

接口 vs 类型别名

接口和类型别名在许多场景下可以互换使用，但接口支持声明合并（Declaration Merging），即多个同名接口会自动合并。接口更适合定义对象的形状和类的契约，而类型别名更适合定义联合类型、元组等复杂类型。

基础接口定义

TypeScript
// 定义接口
interface User {
    name: string;
    age: number;
    email: string;
}

// 使用接口
const user: User = {
    name: "张三",
    age: 25,
    email: "zhangsan@example.com"
};

// 可选属性
interface UserProfile {
    name: string;
    age: number;
    phone?: string;      // 可选属性
    address?: string;
}

// 只读属性
interface Config {
    readonly host: string;
    readonly port: number;
}

const config: Config = { host: "localhost", port: 3000 };
// config.port = 3001; // ❌ 错误：无法为 "port" 赋值，因为它是只读属性

接口继承

TypeScript
// 单接口继承
interface Animal {
    name: string;
    age: number;
}

interface Dog extends Animal {
    breed: string;
    bark(): void;
}

// 多接口继承
interface Swimmable {
    swim(): void;
}

interface Flyable {
    fly(): void;
}

interface Duck extends Animal, Swimmable, Flyable {
    quack(): void;
}

const duck: Duck = {
    name: "唐老鸭",
    age: 5,
    swim() { console.log("游泳"); },
    fly() { console.log("飞行"); },
    quack() { console.log("嘎嘎叫"); }
};

声明合并（Declaration Merging）

TypeScript
// 同名接口会自动合并
interface Window {
    myCustomProperty: string;
}

interface Window {
    anotherProperty: number;
}

// Window 现在同时拥有 myCustomProperty 和 anotherProperty

// 接口合并时，同名属性类型必须兼容
interface Box {
    width: number;
}

interface Box {
    height: number;
    // width: string; // ❌ 错误：width 类型不兼容
}

// 函数接口合并
interface Counter {
    (): number;
}

interface Counter {
    count: number;
}

// Counter 现在既是函数又是对象
声明合并的妙用：声明合并在扩展第三方库的类型时非常有用。例如，当 Express 请求对象需要添加自定义属性时，可以通过声明合并来扩展 Express.Request 接口。

命名空间与接口合并

TypeScript 
// 命名空间与类合并 - 添加静态成员类型
class API {
    constructor(public url: string) {}
}

namespace API {
    export interface Config {
        timeout: number;
        retries: number;
    }

    export function create(url: string, config?: Partial<Config>): API {
        return new API(url);
    }

    export const DEFAULT_CONFIG: Config = {
        timeout: 5000,
        retries: 3
    };
}

// 现在 API 既有实例成员也有命名空间导出
const api = new API("https://api.example.com");
const api2 = API.create("https://api.example.com", { timeout: 10000 });

// 命名空间与枚举合并 - 扩展枚举功能
enum Color {
    Red = "RED",
    Green = "GREEN",
    Blue = "BLUE"
}

namespace Color {
    export function fromString(value: string): Color | undefined {
        return Object.values(Color).find(
            v => typeof v === "string" && v.toLowerCase() === value.toLowerCase()
        ) as Color | undefined;
    }

    export const ALL: Color[] = [Color.Red, Color.Green, Color.Blue];
}

// 模块增强（Module Augmentation）
// 扩展 Express 的 Request 类型
declare module "express" {
    interface Request {
        userId?: string;
        role?: "admin" | "user" | "guest";
        sessionId?: string;
    }
}

// 使用时 Express Request 自动带上新属性
app.get("/profile", (req, res) => {
    console.log(req.userId);  // ✅ string | undefined
    console.log(req.role);     // ✅ "admin" | "user" | "guest"
});

5. 类型别名

类型别名（Type Alias）使用 type 关键字为类型创建一个新名称。它比接口更灵活，可以表示接口无法表达的类型。

TypeScript
// 基础类型别名
type StringOrNumber = string | number;
type ID = string | number;
type Callback = (data: any) => void;

// 对象类型别名
type Point = {
    x: number;
    y: number;
};

// 函数类型别名
type Formatter = (input: string) => string;

// 联合类型
type Status = "active" | "inactive" | "pending";

// 映射类型（后面会详细讲解）
type PartialUser = Partial<User>;

// 交叉类型 - 合并多个类型
type Named = { name: string };
type Aged = { age: number };
type Person = Named & Aged;
// Person 等同于 { name: string; age: number }

// 条件类型
type IsString<T> = T extends string ? true : false;
type A = IsString<"hello">;  // true
type B = IsString<42>;       // false
接口与类型别名的选择：定义对象形状时优先使用 interface，因为它支持声明合并和错误信息更友好。使用 type 定义联合类型、交叉类型、元组和更复杂的类型操作。

6. 联合类型

联合类型（Union Types）允许一个变量可以是多种类型中的一种。使用 | 操作符连接多个类型。

基础联合类型

TypeScript
// 基础联合类型
let value: string | number;
value = "hello";  // ✅
value = 42;       // ✅
// value = true;  // ❌ 类型不匹配

// 可辨识联合（Discriminated Unions）
interface Circle {
    kind: "circle";
    radius: number;
}

interface Rectangle {
    kind: "rectangle";
    width: number;
    height: number;
}

interface Triangle {
    kind: "triangle";
    base: number;
    height: number;
}

type Shape = Circle | Rectangle | Triangle;

function calculateArea(shape: Shape): number {
    switch (shape.kind) {
        case "circle":
            return Math.PI * shape.radius ** 2;
        case "rectangle":
            return shape.width * shape.height;
        case "triangle":
            return (1 / 2) * shape.base * shape.height;
    }
}

交叉类型

TypeScript
// 交叉类型 - 合并所有类型的属性
type HasName = { name: string };
type HasAge = { age: number };
type HasEmail = { email: string };

type PersonInfo = HasName & HasAge & HasEmail;

const person: PersonInfo = {
    name: "张三",
    age: 25,
    email: "zhangsan@example.com"
};

// 交叉类型与接口合并的区别
// 交叉类型：直接合并，同名属性必须兼容
// 接口合并：方法签名会重载

模板字面量类型（Template Literal Types）

TypeScript
// 模板字面量类型 - TypeScript 4.1+
type Color = "red" | "green" | "blue";
type Size = "small" | "medium" | "large";

// 自动生成所有组合
type ColorSize = `${Color}-${Size}`;
// "red-small" | "red-medium" | "red-large" |
//  "green-small" | "green-medium" | "green-large" |
//  "blue-small" | "blue-medium" | "blue-large"

// 实用场景：事件名称推断
type EventName = "click" | "scroll" | "mouseover";
type EventHandler = `on${Capitalize<EventName>}`;
// "onClick" | "onScroll" | "onMouseover"

// 内置字符串操作类型
type Upper = Uppercase<"hello">;     // "HELLO"
type Lower = Lowercase<"HELLO">;     // "hello"
type Cap = Capitalize<"hello">;      // "Hello"
type Unc = Uncapitalize<"Hello">;   // "hello"

字符串操作模式

TypeScript 
// 类型安全的 CSS 属性名
type CSSUnit = "px" | "em" | "rem" | "%" | "vh" | "vw";
type CSSValue = `${number}${CSSUnit}`;
// "0px" | "0em" | ... | "42px" | "42em" | ...

function setStyle(element: HTMLElement, prop: string, value: CSSValue) {
    element.style.setProperty(prop, value);
}

// 类型安全的事件系统 - 事件名与处理函数匹配
type HTMLElementEvent = "click" | "focus" | "blur";
type EventHandlers = {
    [K in HTMLElementEvent as `on${Capitalize<K>}`]: () => void;
};
// { onClick: () => void; onFocus: () => void; onBlur: () => void; }

// 字面量类型提取 - 从路径中解析参数
type ExtractRouteParams<T extends string> =
    T extends `${string}:${infer Param}/${infer Rest}`
        ? Param | ExtractRouteParams<`/${Rest}`>
        : T extends `${string}:${infer Param}`
        ? Param
        : never;

type Params = ExtractRouteParams<"/users/:id/posts/:postId">;
// "id" | "postId"

// 模板字面量递归 - 字符串转为 kebab-case
type CamelToKebab<T extends string> =
    T extends `${infer Head}${infer Tail}`
        ? Head extends Uppercase<Head>
            ? Head extends Lowercase<Head>
                ? `${Head}${CamelToKebab<Tail>}`
                : `-${Lowercase<Head>}${CamelToKebab<Tail>}`
            : `${Head}${CamelToKebab<Tail>}`
        : T;

type Kebab = CamelToKebab<"backgroundColor">;
// "background-color"

// 类型安全的 JSON Path 访问
type Join<T extends string[], D extends string> =
    T extends [infer First extends string, ...infer Rest extends string[]]
        ? Rest[0] extends undefined
            ? First
            : `${First}${D}${Join<Rest, D>}`
        : "";

type Path = Join<["users", "123", "posts"], "/">;
// "users/123/posts"

7. 泛型

泛型（Generics）是 TypeScript 中最强大的特性之一。它允许创建可复用的组件，这些组件可以支持多种类型而非仅仅一种。泛型类似于类型参数，使用 <T> 语法声明。

泛型的本质

泛型本质上是类型的函数。就像普通函数接收值作为参数一样，泛型函数接收类型作为参数。这使得我们能够编写既类型安全又高度可复用的代码。

基础泛型

TypeScript
// 泛型函数
function identity<T>(arg: T): T {
    return arg;
}

// 显式指定类型参数
const output1 = identity<string>("hello");

// 类型推断（推荐）
const output2 = identity("hello"); // 自动推断为 string

// 泛型接口
interface ApiResponse<T> {
    code: number;
    message: string;
    data: T;
}

// 使用泛型接口
interface User { id: number; name: string; }
interface Product { id: number; title: string; price: number; }

const userResponse: ApiResponse<User> = {
    code: 200,
    message: "success",
    data: { id: 1, name: "张三" }
};

const productResponse: ApiResponse<Product[]> = {
    code: 200,
    message: "success",
    data: [{ id: 1, title: "手机", price: 4999 }]
};

泛型约束

TypeScript
// 使用 extends 约束泛型
interface HasLength {
    length: number;
}

function logLength<T extends HasLength>(arg: T): T {
    console.log(`长度: ${arg.length}`);
    return arg;
}

logLength("hello");      // ✅ string 有 length
logLength([1, 2, 3]);     // ✅ array 有 length
logLength({ length: 10 }); // ✅ 对象有 length
// logLength(123);       // ❌ number 没有 length

// keyof 约束
function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] {
    return obj[key];
}

const user = { name: "张三", age: 25 };
getProperty(user, "name");  // ✅ 返回 string
getProperty(user, "age");   // ✅ 返回 number
// getProperty(user, "email"); // ❌ "email" 不是 user 的键

泛型默认值与多类型参数

TypeScript
// 泛型默认值
interface PageResponse<T, E = Error> {
    data: T;
    error?: E;
}

// 使用默认值
const res1: PageResponse<string[]> = {
    data: ["a", "b"]
};

// 覆盖默认值
const res2: PageResponse<User, ApiError> = {
    data: { id: 1, name: "张三" },
    error: { code: 404, message: "未找到" }
};

// 多类型参数泛型
function merge<T, U>(obj1: T, obj2: U): T & U {
    return { ...obj1, ...obj2 };
}

const merged = merge(
    { name: "张三" },
    { age: 25 }
);
// 类型为 { name: string } & { age: number }

// 泛型类
class Stack<T> {
    private items: T[] = [];

    push(item: T): void {

21. 最佳实践

以下是 TypeScript 开发中推荐的最佳实践，遵循这些原则可以编写出更安全、更可维护的代码。

核心原则

优先类型安全，其次便利性。TypeScript 的价值在于编译时捕获错误。当类型安全与便利性冲突时，选择类型安全。宁可多写几行类型定义，也不要在运行时遇到 undefined is not a function 的错误。

启用严格模式

TypeScript
{
    "compilerOptions": {
        "strict": true,
        // 等同于启用以下所有选项：
        "noImplicitAny": true,      // 禁止隐式 any
        "strictNullChecks": true,   // 严格空值检查
        "strictFunctionTypes": true, // 严格函数类型
        "strictBindCallApply": true, // 严格绑定调用
        "noImplicitThis": true,      // 禁止隐式 this
        "alwaysStrict": true,        // 始终输出严格模式
        "useUnknownInCatchVariables": true
    }
}

避免 any

TypeScript
// ❌ 不推荐
function process(data: any): any {
    return data.foo.bar;
}

// ✅ 推荐 - 使用 unknown
function process(data: unknown): unknown {
    if (
        typeof data === "object" &&
        data !== null &&
        "foo" in data
    ) {
        const obj = data as { foo: { bar: unknown } };
        return obj.foo.bar;
    }
    throw new Error("无效数据");
}

// ✅ 推荐 - 使用具体类型
interface ProcessedData {
    foo: { bar: string };
}

function processBetter(data: ProcessedData): string {
    return data.foo.bar;
}

// ✅ 推荐 - 使用泛型
function identity<T>(arg: T): T {
    return arg;
}

总结

TypeScript 核心要点回顾

1. 类型推断优先：利用 TypeScript 的类型推断能力，减少不必要的类型注解。

2. 严格模式必备：始终启用 strict: true，获得最全面的类型检查。

3. 避免 any：使用 unknown、具体类型或泛型代替 any。

4. 利用结构化类型：理解 TypeScript 的结构化类型系统，编写更灵活的类型。

5. 渐进式迁移：大型 JavaScript 项目可以逐步迁移到 TypeScript，不需要一次性重写。

6. 善用工具类型：使用 Partial、Pick、Omit 等内置工具类型简化类型定义。

7. 类型安全的 API：使用字面量类型、可辨识联合和 Result 模式设计类型安全的接口。

22. 装饰器 (Decorators)

Stage 3 装饰器

TypeScript 5.0+ 支持 TC39 Stage 3 标准的装饰器。装饰器是可以在类声明、方法、属性或访问器上附加元数据或修改行为的函数。它们是 Angular、NestJS 等框架的核心机制。

TypeScript 
// 类装饰器
function sealed(constructor: Function) {
    Object.seal(constructor);
    Object.seal(constructor.prototype);
}

// 方法装饰器
function log(
    target: any,
    context: ClassMethodDecoratorContext<any, any>
) {
    const name = context.name;
    return function(this: any, ...args: any[]) {
        console.log(`Calling ${String(name)} with`, args);
        const result = context.value.call(this, ...args);
        console.log(`Result: ${result}`);
        return result;
    };
}

// 带参数的装饰器工厂
function throttle(ms: number) {
    return function(
        target: any,
        context: ClassMethodDecoratorContext<any, Function>
    ) {
        let lastCall = 0;
        context.addInitializer(function() {
            const original = this[context.name] as Function;
            (this as any)[context.name] = function(...args: any[]) {
                const now = Date.now();
                if (now - lastCall >= ms) {
                    lastCall = now;
                    return original.apply(this, args);
                }
            };
        });
    };
}

// 属性装饰器
function range(min: number, max: number) {
    return function(
        target: any,
        context: ClassFieldDecoratorContext
    ) {
        context.addInitializer(function() {
            const value = (this as any)[context.name];
            if (value < min || value > max) {
                throw new Error(`${String(context.name)} must be between ${min} and ${max}`);
            }
        });
    };
}

// 使用装饰器
@sealed
class User {
    @range(0, 150)
    age = 25;

    @log
    greet(name: string): string {
        return `Hello, ${name}`;
    }

    @throttle(1000)
    save() {
        console.log("Saved!");
    }
}

类型收窄的断言

断言函数（Assertion Functions）是一种特殊的函数，调用时如果条件不满足会抛出异常。TypeScript 知道调用后条件一定为真，从而自动收窄类型。

TypeScript 
// 断言函数声明
function assertString(value: unknown): asserts value is string {
    if (typeof value !== 'string') {
        throw new TypeError(`Expected string, got ${typeof value}`);
    }
}

function assertDefined<T>(value: T | null | undefined, name: string): asserts value is T {
    if (value == null) {
        throw new Error(`${name} is required`);
    }
}

function assertNonEmpty(arr: unknown[]): asserts arr is [unknown, ...unknown[]] {
    if (arr.length === 0) {
        throw new Error('Array must not be empty');
    }
}

// 使用示例
function processInput(input: unknown) {
    assertString(input);
    // 此处 input 类型自动收窄为 string
    console.log(input.toUpperCase());
}

function getElement(id: string): HTMLElement {
    const el = document.getElementById(id);
    assertDefined(el, 'Element');
    return el;  // HTMLElement（非 null）
}

// 自定义守卫 vs 断言
function isString(value: unknown): value is string {
    return typeof value === 'string';
}

25. Never 类型进阶

穷尽性检查

never 表示永远不会发生的值。它在联合类型穷尽检查、不可能的类型转换、以及类型体操中扮演关键角色。

TypeScript 
// 穷尽性检查：确保所有情况都被处理
type Shape =
    | { kind: 'circle'; radius: number }
    | { kind: 'rectangle'; width: number; height: number }
    | { kind: 'triangle'; base: number; height: number };

function area(shape: Shape): number {
    switch (shape.kind) {
        case 'circle':
            return Math.PI * shape.radius ** 2;
        case 'rectangle':
            return shape.width * shape.height;
        case 'triangle':
            return 0.5 * shape.base * shape.height;
        default:
            const _exhaustive: never = shape;
            return _exhaustive;
    }
}

// never 在类型运算中
type Exclude2<T, U> = T extends U ? never : T;
type NonNullable2<T> = T extends null | undefined ? never : T;

type EmptyUnion = never;
type Test = EmptyUnion extends string ? 'yes' : 'no';
// 结果是 'no'（因为 never 是空联合，无成员可匹配）

26. Keyof 与索引访问模式

类型安全的属性访问

keyof 提取类型的所有键，T[K] 按键访问值类型。这两个操作符组合使用，可以实现类型安全的属性操作函数，是 TypeScript 类型编程的基础。

TypeScript 
// keyof 基础
interface Person {
    name: string;
    age: number;
    email: string;
}

type PersonKeys = keyof Person;
// "name" | "age" | "email"

// 索引访问
type NameType = Person['name'];  // string
type ValueType = Person[PersonKeys];  // string | number

// 类型安全的 getter
function get<T, K extends keyof T>(obj: T, key: K): T[K] {
    return obj[key];
}

const person: Person = { name: 'Alice', age: 30, email: 'a@b.com' };
const name = get(person, 'name');  // string（自动推断）
// get(person, 'invalid');  // 编译错误

// 类型安全的 setter
function set<T, K extends keyof T>(
    obj: T, key: K, value: T[K]
): void {
    obj[key] = value;
}

// pick：从对象中选取指定属性
function pick<T, K extends keyof T>(
    obj: T, keys: K[]
): Pick<T, K> {
    const result = {} as Pick<T, K>;
    for (const key of keys) {
        result[key] = obj[key];
    }
    return result;
}

// 类型安全的事件系统
type EventMap = {
    click: { x: number; y: number };
    keydown: { key: string };
    scroll: { top: number };
};

function on<K extends keyof EventMap>(
    event: K,
    handler: (payload: EventMap[K]) => void
) {
    // ... 实现
}

on('click', (e) => console.log(e.x, e.y));  // OK
// on('click', (e) => console.log(e.key));  // 编译错误

29. 类型级编程模式

类型体操的系统方法

类型级编程利用 TypeScript 的条件类型、映射类型和递归类型，在编译时进行"计算"。掌握核心模式后，可以实现任意复杂的类型转换。

TypeScript 
// 递归类型：深度 Readonly
type DeepReadonly<T> = T extends object
    ? { readonly [K in keyof T]: DeepReadonly<T[K]> }
    : T;

// 递归类型：Flatten 嵌套数组
type DeepFlatten<T> = T extends (infer U)[]
    ? DeepFlatten<U>
    : T;

type Nested = (number | (string | boolean)[])[];
type Flat = DeepFlatten<Nested>;  // number | string | boolean

// 递归类型：对象路径提取
type ObjectPaths<T, P extends string = ''> =
    T extends object
        ? {
            [K in keyof T]: K extends string
                ? ObjectPaths<T[K], P extends '' ? K : `${P}.${K}`>
                : never
        }[keyof T]
        : P;

interface Config {
    db: { host: string; port: number };
    cache: { ttl: number };
}

type ConfigPaths = ObjectPaths<Config>;
// "db" | "db.host" | "db.port" | "cache" | "cache.ttl"

// 条件类型分发
type ToPromise<T> = T extends any ? Promise<T> : never;
type A = ToPromise<string | number>;  // Promise<string> | Promise<number>

// infer 模式：提取函数参数
type FirstParam<F> = F extends (first: infer P, ...rest: any[]) => any
    ? P : never;

// infer 模式：提取 Promise 值类型
type Awaited<T> = T extends Promise<infer U>
    ? Awaited<U>
    : T;

// 实用：类型安全的 builder 模式
type Builder<T extends Record<string, any>> = {
    [K in keyof T]?: (value: T[K]) => Builder<Omit<T, K>>
} & { build(): T };
类型编程的思维路径：1) 先确定输入和输出类型；2) 用 infer 提取需要的部分；3) 用条件类型做分支；4) 用映射类型做变换；5) 用递归处理嵌套结构。掌握这五步，任何类型转换都能实现。
